# Introduction

Every action performed on a Linux system leaves traces.

When users log in, applications start, services fail, or security events occur, Linux records these activities in **log files**.

Logs provide valuable information for:

* Troubleshooting system problems.
* Monitoring system health.
* Detecting security incidents.
* Investigating attacks.
* Performing forensic analysis.

For a System Administrator or SOC Analyst, logs are one of the most important sources of information.

---

# What is a Log?

A **log** is a record of events generated by the operating system, applications, or services.

Logs help answer questions such as:

* Who logged into the system?
* When did a service start?
* Why did an application fail?
* Which user attempted unauthorized access?
* What changes occurred on the system?

---

# Why Are Logs Important?

Imagine a security guard monitoring a building.

If something unusual happens, the security camera recordings help determine:

* What happened?
* When it happened?
* Who was involved?

Linux logs work the same way.

They provide a historical record of system activity.

---

# Logging vs Monitoring

Although related, logging and monitoring are different concepts.

| Logging                       | Monitoring                      |
| ----------------------------- | ------------------------------- |
| Records events                | Observes events in real time    |
| Stores historical information | Detects current activity        |
| Used for investigations       | Used for alerting and response  |
| Example: `/var/log/auth.log`  | Example: `top`, `journalctl -f` |

---

# Where Are Logs Stored?

Most Linux log files are stored in:

```text
/var/log
```

Example structure:

```text
/var/log
│
├── auth.log
├── syslog
├── kern.log
├── dmesg
├── boot.log
├── apt
├── apache2
└── journal
```

---

# Common Linux Log Files

| Log File            | Purpose                              |
| ------------------- | ------------------------------------ |
| `/var/log/syslog`   | General system messages              |
| `/var/log/auth.log` | Authentication and login events      |
| `/var/log/kern.log` | Kernel messages                      |
| `/var/log/boot.log` | Boot process information             |
| `/var/log/dmesg`    | Hardware and kernel startup messages |
| `/var/log/apache2/` | Apache web server logs               |
| `/var/log/apt/`     | Package installation history         |

> **Note:** Log file locations can vary slightly between Linux distributions. For example, Red Hat–based systems commonly use `/var/log/secure` instead of `/var/log/auth.log` for authentication logs.

---

# Authentication Logs

Authentication logs contain information related to:

* User logins
* Failed login attempts
* SSH logins
* Sudo usage
* Authentication failures

Example:

```text
Jul 25 09:10:22 ubuntu sshd[1824]: Accepted password for kashif from 192.168.1.20
```

---

# System Logs

System logs record operating system events.

Examples include:

* Service startup
* Network changes
* Hardware events
* Driver messages

---

# Kernel Logs

Kernel logs record events generated by the Linux kernel.

Examples:

* Hardware detection
* Device initialization
* Driver loading
* Kernel errors

# Viewing Log Files

Since logs are plain text files, they can be viewed using several commands.

Common commands:

* `cat`
* `less`
* `head`
* `tail`

---

# Command: cat

## Purpose

Displays the complete contents of a log file.

---

## Syntax

```bash
cat filename
```

Example:

```bash
cat /var/log/syslog
```

> **Note:** `cat` is suitable for small files but not recommended for very large logs.

---

# Command: less

## Purpose

Views large log files one page at a time.

---

## Syntax

```bash
less /var/log/syslog
```

Useful Keys:

| Key   | Function      |
| ----- | ------------- |
| Space | Next Page     |
| b     | Previous Page |
| /     | Search        |
| q     | Quit          |

# Command: head

## Purpose

Displays the beginning of a file.

---

## Syntax

```bash
head /var/log/syslog
```

Example Output:

Displays the first 10 lines.

---

## Display First Five Lines

```bash
head -5 /var/log/syslog
```

---

# Command: tail

## Purpose

Displays the last lines of a file.

---

## Syntax

```bash
tail /var/log/syslog
```

---

## Monitor Logs in Real Time

```bash
tail -f /var/log/syslog
```

The `-f` option continuously displays new log entries as they are written.

This is extremely useful during troubleshooting and incident response.

# Command: grep

## Purpose

Searches log files for specific words or patterns.

---

## Syntax

```bash
grep "keyword" filename
```

Example:

```bash
grep "Failed" /var/log/auth.log
```

Example Output:

```text
Failed password for admin from 192.168.1.100
```

Another example:

```bash
grep "error" /var/log/syslog
```

---

# Command: journalctl

## Purpose

Displays logs collected by the `systemd` journal.

Modern Linux distributions use `systemd` to collect and manage logs.

---

## View All Logs

```bash
journalctl
```

---

## Show Recent Logs

```bash
journalctl -n 20
```

Displays the last 20 log entries.

---

## Follow Logs in Real Time

```bash
journalctl -f
```

Displays new log entries as they are generated.

---

## View Logs Since Boot

```bash
journalctl -b
```

---

## View Logs for a Specific Service

```bash
journalctl -u ssh
```

Replace `ssh` with the name of another service as needed.

# Log Rotation

If log files continued growing indefinitely, they would eventually consume all available disk space.

Linux solves this problem using **log rotation**.

Log rotation:

* Archives old log files.
* Compresses old logs.
* Creates new log files.
* Deletes very old logs based on retention policies.

The `logrotate` utility automates this process on most Linux systems.

Example:

```text
syslog
syslog.1
syslog.2.gz
```

# Blue Team Perspective

Logs are one of the most valuable sources of evidence during a security investigation.

SOC analysts routinely examine logs to:

* Detect brute-force login attempts.
* Identify unauthorized SSH access.
* Investigate malware execution.
* Review privilege escalation events.
* Detect unusual service activity.
* Build a timeline of an incident.

Some of the most frequently analyzed log sources include:

* Authentication logs
* Web server logs
* Firewall logs
* DNS logs
* Application logs
* System journal logs

Effective log analysis enables analysts to identify malicious behavior, understand attacker actions, and support incident response.

---

# Common Mistakes

* Ignoring log warnings and errors.
* Using `cat` on very large log files.
* Deleting logs before investigating incidents.
* Failing to synchronize system time, making timestamps unreliable.
* Not checking distribution-specific log locations.

---

# Best Practices

* Review authentication logs regularly.
* Use `tail -f` during troubleshooting.
* Archive logs according to your organization's retention policy.
* Monitor disk usage to prevent log storage issues.
* Protect log files from unauthorized modification.
