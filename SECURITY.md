# Reporting Security Issues

If you discover a security issue related to this repository, please **do not publish it publicly first**.

Examples include:

- Malicious or harmful code
- Dangerous example commands
- Insecure scripts
- Secrets or credentials accidentally committed
- Broken authentication examples
- Supply chain concerns (dependencies, downloads, or external resources)

Instead, please:

1. Open a **private security advisory** if available.
2. If private reporting is unavailable, contact the repository maintainer directly.
3. Include enough information to reproduce and understand the issue.

Please provide:

- A clear description of the issue
- Steps to reproduce
- The affected file(s)
- The potential impact
- Suggested mitigation (if known)

## Documentation Issues

Examples:

- Commands that may unintentionally damage a system
- Unsafe configuration recommendations
- Incorrect security guidance
- Outdated security practices

---

## Dependencies

If you notice that a recommended tool or dependency has a known critical vulnerability, please report it.

Examples include:

- Vulnerable software versions
- Deprecated installation methods
- Broken download links
- Compromised third-party resources

# Responsible Disclosure

Please allow reasonable time for reported issues to be investigated and addressed before publicly disclosing them.

Responsible disclosure helps protect users who rely on this repository for learning.

This repository is intended for:

- Educational use
- Home lab environments
- Personal learning
- Cybersecurity training

Readers are encouraged to review the official documentation for all tools before deploying them in production environments.

---

# Safe Usage

Many guides involve:

- Virtual machines
- Networking
- Security monitoring
- System configuration

To reduce risk:

- Perform exercises in an isolated lab.
- Do not test against systems you do not own or have permission to assess.
- Keep your operating systems and software up to date.
- Create snapshots before making significant changes.
- Back up important data before experimentation.

# Security Best Practices

We recommend the following when building your home lab:

- Keep operating systems updated.
- Use strong passwords.
- Enable multi-factor authentication where possible.
- Regularly update security tools.
- Monitor system logs.
- Create VM snapshots before major changes.
- Back up important files and configurations.
