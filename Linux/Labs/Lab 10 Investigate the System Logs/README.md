# Lab 10 – Logging & Monitoring

## Scenario

The Security Operations Center (SOC) has detected multiple failed login attempts on a critical Linux server. There is no evidence that the attacker gained access, but the team needs to determine what happened by analyzing the system logs.

As a Blue Team Analyst, your responsibility is to examine Linux log files, identify suspicious events, and determine whether the system has been compromised.

---

# Mission

Investigate Linux log files and monitor system activity to identify security events, authentication attempts, and indicators of compromise.

---

# Story

Early this morning, the SOC received an alert from its monitoring system.

Several failed login attempts were detected from an unknown source. No malware has been found yet, but the investigation cannot continue until someone reviews the system logs.

Your team leader turns to you and says:

> *"Logs never lie. Every login, every command, and every system event leaves a trace. Your job is to follow those traces and uncover the truth."*

Your mission is to investigate the server using Linux logging and monitoring tools.

---

# Your Tasks

Complete the following tasks using Linux logging and monitoring tools.

### Task 1 – Locate System Logs

Explore the directory where Linux stores log files.

Identify logs related to:

* Authentication
* System events
* Kernel messages
* Package management

Record your observations.

---

### Task 2 – Monitor Logs in Real Time

Observe a log file while generating new system activity.

Watch how log entries appear as events occur.

---

### Task 3 – Investigate Login Activity

Review authentication logs.

Identify:

* Successful logins
* Failed login attempts
* Usernames involved
* Login timestamps

---

### Task 4 – Search for Security Events

Search the logs for:

* Failed authentication
* SSH activity
* Sudo usage
* User account changes

Document your findings.

---

### Task 5 – Review System Service Logs

Inspect logs generated by important Linux services.

Determine whether any services reported warnings or errors.

---

### Task 6 – Monitor System Events

Use Linux monitoring tools to examine recent system events.

Identify:

* Service restarts
* Boot events
* Critical warnings
* Error messages

---

### Task 7 – Create an Investigation Timeline

Build a timeline of important events using the information collected from multiple log sources.

Include:

* Time
* Event
* User
* Description

---

### Task 8 – Write an Incident Report

Prepare a report summarizing:

* Logs reviewed
* Security events identified
* Evidence collected
* Timeline of events
* Recommendations

# Blue Team Insight

Log analysis is one of the most valuable skills for a SOC Analyst.

Security teams use logs to:

* Detect brute-force attacks.
* Investigate unauthorized access.
* Identify privilege escalation.
* Monitor administrative activity.
* Detect persistence techniques.
* Build timelines during incident response.
* Support forensic investigations.

Without logs, understanding what happened during a security incident becomes significantly more difficult.
